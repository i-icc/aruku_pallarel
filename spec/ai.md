# エージェント設計（ADK / LLM）

## 使用モデル
- Gemini 3 Flash Preview（Google AI / Vertex AI）
- Vertex AI で Gemini 3 preview を使う場合は `GOOGLE_CLOUD_LOCATION=global` を前提とする

## 目的
- 未踏地点の体験を言語化し、散歩後の余韻をつくる
- ルート案内や意思決定の代行はしない

## 入力（最小）
- 候補地点の緯度経度

## 出力形式（JSON）
```json
{
  "message": "この道、静かで木陰が多いかも。午後に歩くと心地よさそう。"
}
```

## 生成ルール
- 1〜2文、短く余白を残す
- 断定を避け「かも」「〜そう」などの表現を使う
- ナビ/指示/危険行為の促進はしない
- 具体的な住所は不要（緯度経度で十分）
- ユーザーの現在行動を変える提案はしない（“次回”を前提にする）
- 「場所の手がかり」「質感（光/風/音）」「余韻（次回の気配）」を小さく重ねる
- 固有名詞は信頼できる根拠がある場合のみ使用し、ない場合は一般表現に留める

## URL生成
- URL は Job 側で組み立てる（Google Maps の DMS 形式）

## マルチエージェント構成（ADK）
- 並列で「手がかり」「質感」「余韻」を生成し、最後に合成して 1〜2 文に整える
- 中間メモは ADK のセッション状態に保持し、最終出力のみ JSON を返す
- 中間メモは短文テキストとし、JSON 形式では出力しない

### 生成フロー
1. 近くの手がかり（地形/小さな要素）を短文で作る
2. 質感（光/風/音/影など）を短文で作る
3. 余韻（次回の気配）を短文で作る
4. 3 つを合成し、ルールを満たす 1〜2 文に整える
5. JSON 形式で返す（`{ "message": "..." }`）

## 失敗時の扱い
- 生成に失敗した場合は通知せず、再試行で回復する
